格式化到底做了什么

      

        解析 → 重新序列化。这里没有做任何「猜测式修复」：只要 JSON.parse 能通过，
        输出就是合法的 JSON；解析不通过，就直接报错而不是硬掰一个结果出来。
      

      

        这一点很重要。有些工具会把单引号自动改成双引号、把尾逗号删掉，看起来「很智能」——
        但它也可能悄悄改掉你数据里的一个字符，而你不会发现。这里宁可报错。
      


      
键名排序是怎么排的

      

        排序是递归的：对象里的每一层都会按键名重排，数组本身保持原有顺序（数组的顺序是数据的一部分，不能动），
        但数组里的对象照样会排。比较用的是 Unicode 码位，不是「人类语言习惯」——
        所以大写字母排在小写字母前面，数字排在最前。
      

      

        一个容易被当成 bug 的现象： 如果键名是纯数字（比如 "2"、"10"），
        即使选了 Z → A 也永远按升序输出。这不是没生效 —— JavaScript 规定对象的整数键必须按数值升序枚举，
        任何 JSON.stringify 都会遵守这条规则。
      


      
大数字会丢精度，这不是本工具的问题

      

        JavaScript 的数字是双精度浮点，能精确表示的整数上限是 253-1（9007199254740991，16 位）。
        超过这个长度的整数，JSON.parse 在解析那一刻就已经把它四舍五入了。
      

      

        所以像雪花算法生成的 19 位 ID、数据库 bigint 主键，进到这个页面再出去就会变成别的数字。
        如果你看到页面上出现黄色警告，说明数据里有这种值 —— 这类数据不要用任何基于 JS 的工具处理，
        或者让后端把长整型序列化成字符串。
      


      
常见问题

      

        

          为什么报错说「有多余的尾逗号」
          
JS 对象字面量允许 {"a":1,} 这样写，JSON 不允许。最后一个成员后面不能有逗号，这是最常见的差别。

        

        

          能处理带注释的 JSON 吗
          
不能，标准 JSON 不支持注释。如果你在用 JSON5 / JSONC（VS Code 配置文件那种），需要先把注释去掉 —— 页面会提示你注释在哪一行。

        

        

          数据量有上限吗
          
没有硬限制，取决于浏览器内存。几十 MB 的 JSON 也能处理，但输入框会明显变卡，建议超过 5MB 的直接用代码处理。

        

        

          排序会改变数据含义吗
          
不会。对象的键顺序不影响语义，任何解析器都不应该依赖它。但如果有代码在遍历键时依赖顺序（比如生成签名串），那要注意 —— 这种情况本来就不该依赖顺序。
