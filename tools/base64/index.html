图片转 Base64

把图片转成 Base64 编码或 Data URI，可直接内嵌到 CSS、HTML、Markdown 里，省掉一次 HTTP 请求。转换在你的浏览器里完成。

本地转换：图片不会上传，适合处理未公开的设计稿和素材。

Base64 是什么，为什么要把图片塞进去

      

        Base64 是一种把二进制数据编码成纯文本的方案。图片本身是二进制，浏览器只认二进制，
        但 CSS、HTML、JSON 这些地方只能放文本 —— Base64 解决的正是这个问题：把图片变成一串能用文本表示的字符。
      

      

        最典型的用法是把小图标直接写进 CSS：
      

      
.icon-search {
  background-image: url("data:image/svg+xml;base64,PHN2ZyB4bWxucz0i...");
}

      

        这样做的好处是省掉一次图片请求。图标很小的时候，建立连接的开销（DNS、TCP、TLS）比传输数据本身还大，
        内嵌反而更快。
      


      
什么时候不该用

      

        别把大图转 Base64。 Base64 会让体积膨胀约 33%，而且这部分数据无法被浏览器单独缓存 ——
        图片更新时整个 CSS/HTML 文件都要重新下载。超过 10KB 就该用独立文件。
      

      
    
        
  • 适合：1–5KB 的图标、logo、加载动画、邮件模板里的图片（很多邮件客户端会拦截外链图片）
    • 
        
  • 不适合：照片、大尺寸 banner、会被复用的素材
    • 
        
  • 性能提示：如果图标是单色的，用内联 SVG 比 Base64 编码的 PNG 小得多，而且可以改颜色
    • 
      


      
体积怎么算的

      

        每 3 个字节编成 4 个字符，所以理论膨胀率是 4/3 ≈ 133%。如果再加上 data:image/png;base64,
        这样的前缀，实际增长会略高一点。页面上的「膨胀」百分比就是按这个算的。
      


      
常见问题

      

        

          转换后的文字可以直接粘到项目里吗
          
可以。上面的格式标签会自动套好语法 —— 选 CSS 就直接给你 background-image: url(...)，选 HTML 就是完整的 <img> 标签。复制粘贴即可。

        

        

          为什么我的图片转出来特别长
          
Base64 是原文的 1.33 倍，一张 100KB 的图片会变成 13 万字符。如果觉得太长，先用压缩工具把图片压小，再回来转。

        

        

          SVG 也能转吗
          
能，但没必要。SVG 本身就是文本格式，直接内联进 HTML 更好 —— 体积更小，还能用 CSS 控制颜色。只有当你必须把它当作图片资源引用时，才需要 Base64。

        

        

          支持 WebP 和 AVIF 吗
          
支持。Data URI 里的 MIME 类型会跟着原文件走，浏览器的解码能力和普通图片请求一致。
