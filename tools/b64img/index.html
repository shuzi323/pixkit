Base64 转图片到底做了什么

Base64 是一串纯文本，本身不是图片。它内部装着图片的二进制字节，只是用 64 个可打印字符表示出来。 「解码」要做的就是把文本还原成字节，再交给浏览器还原成画面 —— 这一步不需要联网，也不需要服务器。

所以这个工具做的事情很简单：解析字符串 → 还原字节 → 推测格式 → 生成可下载的文件。 你看到的那张预览图和最后下载的文件，是同一份数据。

不写 data: 前缀也能识别

很多工具要求你必须粘贴完整的 data:image/png;base64,...，少一段就报错。 这里换了个办法：直接读字节头部的「魔数」（magic number），也就是每种图片格式固定的开头几个字节。

常见格式的魔数： PNG 是 89 50 4E 47，JPEG 是 FF D8 FF， GIF 是 47 49 46，WebP 是 RIFF....WEBP，BMP 是 42 4D， SVG 则是文本形式的 <svg 开头。

这样做的好处是两个：一是纯 Base64 字符串能直接用，二是当有人把 PNG 的数据错标成 image/jpeg 时， 你拿到的仍然是正确的 .png 文件，而不是一个改错扩展名、某些软件打不开的文件。

为什么有时候解不出来

  • 字符串被截断了：Base64 的长度必须是 4 的倍数，少几个字符就解不出来。常见于从聊天窗口复制长文本时被折叠。
  • 混进了别的字符：换行和空格会自动忽略，但引号、HTML 标签、Markdown 包裹符号不会 —— 粘贴前记得去掉。
  • 本来就是加密过的内容：Base64 是编码不是加密，但它经常被用来包一层加密后的数据。那种数据解出来是乱码，不是图片。

常见问题

支持多大的图片

浏览器内存允许就能解，实测几十 MB 的 Base64 也能处理。不过文本越大，输入框响应越慢，超过 5MB 的字符串建议直接用代码处理。

能把图片转回 Base64 吗

可以，用同站的图片转 Base64：上传图片，生成 Data URI、CSS、HTML 或 Markdown 格式的引用。两个工具用的是同一套编码规则。

下载的文件名是什么

统一叫 base64-image.png（扩展名按实际格式变）。Base64 数据里不包含文件名信息，所以没法还原成原始名字。

SVG 也能解吗

能。SVG 的 Data URI 有两种写法：;base64, 编码的，和直接内联 XML 的（URL 编码）。两种都能识别，解出来是 .svg 文件。
